# Spec Delta

## Purpose

Defines benchmark reports that compare strategy families fairly and keep portfolio performance, model accuracy, shaped training rewards and compute cost in separate, non-interchangeable sections.

## ADDED Requirements

### Requirement: Separate reporting sections
A benchmark report SHALL contain separate sections for portfolio performance, model accuracy (only for strategies that make predictions), training rewards (only for learned strategies) and compute cost. Report schemas MUST NOT combine metrics from different sections into one score.

#### Scenario: Classical optimizer report
- **WHEN** a report covers minimum-variance and the controls
- **THEN** the model accuracy and training reward sections are marked not applicable, and portfolio and cost sections are filled

#### Scenario: Combined score requested
- **WHEN** a report configuration asks for one blended score of return and accuracy
- **THEN** report generation fails with `VALIDATION_FAILED`

### Requirement: Portfolio performance metrics
The portfolio section SHALL report, per strategy and per evaluation period: net and gross cumulative return, annualized volatility, Sharpe ratio with the stated risk-free source, maximum drawdown, turnover and total transaction costs, all computed by the common evaluator.

#### Scenario: Metrics present
- **WHEN** a benchmark completes
- **THEN** every strategy row includes each listed metric for each walk-forward fold, the holdout (when evaluated) and the aggregate

### Requirement: Compute cost reporting
The cost section SHALL report, per run, instance type, instance count, billed runtime seconds, the estimated cost from the pre-flight check and, when available, the actual billed cost, labeled as estimated or actual.

#### Scenario: Actual cost not yet available
- **WHEN** billing data for a run is not yet available
- **THEN** the report shows the estimated cost labeled `estimated` and the actual cost as pending

### Requirement: Period labeling
Each reported number SHALL be labeled with its period type: `walk_forward_fold`, `validation`, `holdout` or `prospective_paper`, and with `synthetic: true` when computed on synthetic data.

#### Scenario: Holdout and validation side by side
- **WHEN** a report shows validation and holdout results
- **THEN** they are in separately labeled columns and the holdout access log is attached

### Requirement: Variability disclosure
For strategies with randomness (scenario generation, seeds), the report SHALL show the number of seeds or scenario draws and the dispersion of each portfolio metric across them, not only the best run.

#### Scenario: CVaR with several seeds
- **WHEN** scenario-CVaR runs with 5 scenario seeds
- **THEN** the report shows each metric's mean and range across the 5 seeds

### Requirement: Deterministic report generation
Reports SHALL be generated by deterministic code from stored run results, with a checksum, and any narrative text MUST be kept separate from the numeric evidence.

#### Scenario: Regenerate report
- **WHEN** a report is regenerated from the same run results
- **THEN** its numeric content and checksum are identical
