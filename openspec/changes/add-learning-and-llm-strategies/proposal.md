# Proposal

## Why

The brief asks FinanceModel to benchmark learned and language-model strategies (RL, a self-hosted Qwen3.6-27B agent swarm and TypeSafe Jev decision classification) against the controls and classical optimizers under the same evaluator. These families need GPU or Training-Job compute, carry leakage and reproducibility risks that classical baselines do not, and can consume most of the USD 25 GPU allocation of the USD 50 total AWS budget in one run. So they need their own requirements for seeds, serving lifecycle, cost gating and honest reporting before any code is written. This is FinanceModel phase 2. It builds on `add-research-job-foundation` and corresponds to contracts phase 3 (contracts design D7).

## What Changes

- Add **RL strategies**: PPO and SAC trained as SageMaker Training Jobs in the common simulator, with explicit, versioned state, action and reward definitions, multiple seeds, and validation-only model selection. DQN is allowed only with an explicit discrete action design.
- Add **Qwen3.6-27B weight staging** owned by FinanceModel: the pinned Hugging Face revision `Qwen/Qwen3.6-27B@6a9e13bd6fc8f0983b9b99948120bc37f49c13e9` staged into FinanceModel research storage by a CPU job with a per-file SHA-256 manifest written last, reusing the discovered pattern. It never reads or modifies the other project's bucket or role, and never substitutes another Qwen release.
- Add a **self-hosted LLM inference lifecycle** with two evaluated options on `ml.g6.12xlarge` with the AWS vLLM DLC: (a) offline vLLM batch runner inside a Training Job (the discovered pattern; GPU Processing quota is 0), and (b) a short-lived SageMaker endpoint with provision, readiness, run and teardown by delete-and-recreate, with measured startup time and no pause/resume. Both use a GPU concurrency lease (quota 1), private IAM-only access, a pre-flight check against the `gpu` budget category (default USD 25), mandatory human approval with a cost estimate for every GPU run, and per-run cost records.
- Add the **Qwen agent-swarm strategy**: fixed roles, a declared arbitration policy, structured outputs validated by deterministic code, every prompt and message logged, and point-in-time inputs only. Reports must state the **pretraining-leakage limitation** of historical LLM backtests.
- Add the **TypeSafe Jev classification strategy** (model identified 2026-10-07, contracts OQ-4 resolved), enabled in phase 2 behind per-run approval. Jev is TypeSafe AI's "System One" decision model, called through the external TypeSafe API (`POST /v1/systemone`). Per instrument and decision date the strategy asks one `choice` question with options {buy, hold, sell}, which makes decisions mutually exclusive by construction. Features are presented as text and bucketed descriptors (the vendor reports weak numeric precision). Yahoo-derived data may reach TypeSafe only for research runs and only as derived descriptors; a pre-send guard rejects any raw price or volume series (RESOLVED 2026-10-07, FM2-OQ-12). Each response's `model` field is recorded for reproducibility. Probabilities are calibrated on our own splits and mapped to position sizes by a deterministic policy under the simulator's constraints. The API key is read from Secrets Manager by name (`finplan/shared/financemodel/jev-api-key`), never stored in the repo. Rate limits and retryable errors (429 with retry-after, 529) are handled with bounded backoff. Jev usage is billed by TypeSafe (prepaid credits), tracked separately and outside the USD 50 AWS budget; the AWS job that calls it counts against `cpu_research`. All historical results carry the pretraining-leakage flag. CI uses a mocked Jev API only. Accuracy is reported separately from profitability.
- Add **strategy promotion** (self-improvement): candidate, then budgeted evaluation, then promotion under user-approved criteria with human approval. Criteria v1 (RESOLVED 2026-10-07, FM2-OQ-7) is a deterministic check: on the untouched holdout test period under the common evaluator, the candidate's net-of-costs return beats the incumbent's AND its maximum drawdown is not worse AND the user's approval is recorded. It never claims guaranteed improvement and never rewrites risk preferences.
- **Out of scope:** live trading, Coinbase, AgentCore payments, wallet spending, paid per-token LLM providers for the swarm strategy, adopting or modifying the other project's Qwen resources, fine-tuning Qwen3.6-27B, and fine-tuning Jev (not offered by the vendor).

## Capabilities

### New Capabilities

- `rl-strategies`: PPO/SAC (and conditional DQN) training and evaluation with explicit state/action/reward, seeds and Training-Job execution.
- `llm-weight-staging`: FinanceModel-owned, checksum-verified staging of the pinned Qwen3.6-27B checkpoint.
- `llm-inference-lifecycle`: GPU serving options, provision/readiness/teardown, GPU concurrency lease, private access, budget gating and per-run cost records.
- `agent-swarm-strategy`: fixed-role Qwen3.6-27B swarm, arbitration, logging, deterministic validation and leakage reporting.
- `jev-classification-strategy`: approval-gated TypeSafe Jev buy/hold/sell `choice` classification through the external API, with text-encoded features, research-only use of Yahoo-derived descriptors with a raw-series payload guard, response-model recording, calibration on our splits, deterministic probability-to-size mapping, rate-limit handling, separate TypeSafe cost tracking and leakage flags.
- `strategy-promotion`: budgeted candidate evaluation and promotion under approved criteria, with criteria v1 as a deterministic holdout check against the incumbent (net-of-costs return, maximum drawdown) plus recorded user approval.

### Modified Capabilities

None. The capabilities of `add-research-job-foundation` are not yet archived. This change adds new capabilities that depend on them (simulator, datasets, job interface, execution controls, registry, reporting) without changing their requirements.

## Impact

- **FinanceModel:** new Training-Job definitions (RL CPU image, Qwen GPU runner image based on the AWS vLLM DLC), an optional endpoint lifecycle orchestrator, a weight-staging job, a GPU lease class, new job types in the job interface, and registry entries for trained RL policies and the swarm and Jev configurations.
- **FinanceLambdasTool:** new job types become submittable through the existing interface. No interface change. Until deployed, they return `DEPENDENCY_UNAVAILABLE`.
- **AWS (us-east-2, single account for beta, gamma and prod):** observed quotas `ml.g6.12xlarge` training 1, endpoint 1, processing 0. About 52 GiB of staged weights in FinanceModel research storage (S3 cost). GPU runs are paid at managed SageMaker rates (not raw EC2 rates). The last observed Qwen batch run took 4754 s, so one run can use a large share of the USD 25 GPU allocation. Every GPU run needs a pre-flight estimate and explicit user approval. Jev jobs need internet egress to the TypeSafe API and read one Secrets Manager secret by name.
- **Budget (user decision 2026-10-07):** USD 50 total AWS budget; this change spends from `gpu` (USD 25) for Qwen and any GPU RL work and from `cpu_research` (USD 7, shared with the foundation) for RL CPU training, weight staging and Jev driver jobs. TypeSafe charges (about USD 0.042 per million input tokens, output free, prepaid credits) are outside AWS and tracked separately.
- **Remaining blockers:** the mode B trial (FM2-OQ-5, mode B only). Promotion criteria v1 is RESOLVED 2026-10-07 (FM2-OQ-7). The real-data provider is RESOLVED 2026-10-07 (foundation FM-OQ-4, contracts OQ-5): the platform's ingestion Lambda or container retrieves SPY daily data with `yfinance` (pinned, `exchange_calendars` XNYS calendar); all strategies here read only foundation datasets built from approved platform snapshots, FinanceModel never calls yfinance and has no yfinance dependency, real-data-derived artifacts are never committed to the public repo, and CI uses the mock provider. Real-data runs now depend only on approved SPY snapshots existing in beta. Non-blocking: weight copy source (FM2-OQ-1), Qwen and Jev training-data cutoffs (FM2-OQ-3, FM2-OQ-10; all historical results flagged meanwhile), exact Jev version pin (FM2-OQ-11). Before the first real Jev API run: a read-through of the TypeSafe terms and confirmation that the job role can read the stored secret. Sending Yahoo-derived descriptors to TypeSafe for research is RESOLVED 2026-10-07 (FM2-OQ-12). See design.md.
