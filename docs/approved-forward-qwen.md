# Approved current-book Qwen decisions

`python -m finplan_model.forward.submit_qwen --experiment EXPERIMENT --slot UTC_SLOT --output PRIVATE_JSON` defaults to a read-only dry-run. Select a fresh actual captured `qwen_swarm_mode_a` slot; requests expire one hour after their original cutoff. `--submit` records only an awaiting-approval GPU request. It never stages weights, grants approval or launches compute. The printed `python scripts/approve_run.py --env beta RUN_ID` requires a separate authorized human; CPU weights staging has its own existing approval.

The existing network-isolated `swarm_mode_a` Training Job receives the exact snapshot/private current-book binding through its bundle channel and the pinned checkpoint/code through the existing weights/code channels. The forward branch precedes historical `daily_scope`; it invokes one native QwenSwarm decision, with at most seven role calls, one revision round,256 output tokens per call and the existing900-second job bound/startup allowance. It changes no portfolio. The common hourly paper engine remains the only executor.

Every exact role message is fsynced to a named immutable local input claim before its backend call. Each public final response is fsynced before dependent messages are prepared. Actual model/revision, source commit, immutable DLC image, offline code SHA and independent approval remain linked. The existing verified archive importer persists original artifacts; hourly reuse embeds their actual content and preserves the original unavailable preflight. A native invalid completed response can produce its documented hold; a backend exception with no response cannot become a successful hold.

A hard container loss can prevent upload of dependent-role evidence. Such output is explicitly unavailable/indeterminate, is unusable for comparison and cannot authorize another automatic GPU launch or fabricated replacement messages. The permanent private context survives idempotency TTL. Recoverable original role responses are replayed only for integrity validation without rerunning their model calls. Failed exported inputs and partial public outputs remain inspectable. Network isolation and the absence of AWS credentials in the GPU container are preserved.

The native signal may be explicitly reused for less than24hours only while its exact approved snapshot, preparation, current book revision and model context match. Distinct approaches/books/protocols never share context. Each managed job has one atomic cost event: estimated GPU cost remains separate from unavailable observed billing; the offline local model has no external vendor transport and records vendor cost0. No historical performance or forecast is invented from its allocation.

Implementation tests use injected controlled backends and fake/moto storage; these are not forward model evaluations. Real coverage still requires the exact verified staged `Qwen/Qwen3.6-27B` revision, separately approved CPU staging/GPU work and an actual successful worker/output readback. Source implementation alone does not satisfy that live gate.

The controller performs the final current-book eligibility check through two beta-only dispatcher GET routes immediately before starting the isolated job. The exact dispatcher role cannot read ordinary user books, write portfolios or directly access platform DynamoDB. Higher-environment policies remain unchanged.

The bounded EC2 importer archives original Model input/response bytes independently in `managed_inference_evidence:<job-id>` observations, including partial failed inputs. Both the inference receipt and the original cost receipt must read back and enqueue their six-field private report-revision tasks before the immutable Model cost outbox is acknowledged. Original inputs remain inspectable after context/date/book changes; missing originals fail visibly and are never replaced.

Before any GPU creation, the controller bounded-reads the existing staged metadata and original MANIFEST, verifies the pinned model/revision/license/file count, freezes their exact bytes/checksums in a Model artifact and CAS-binds its reference into the permanent run/spec. Handoff rejects later staged-manifest drift. After the native backend fully verifies local checkpoint files, a fsynced backend_ready receipt records that verified manifest and original metadata before the first role call. Its original bytes remain inspectable after context loss. Controlled injected backends explicitly have no checkpoint checksum and are never forward evidence. Pure current-book preparation has no AWS SDK dependency in the offline container.
